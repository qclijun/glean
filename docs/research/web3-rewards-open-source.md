# 开源 Web3 奖励活动发现与聚合项目核验

研究快照：2026-10-26，关联 [issue #5](https://github.com/qclijun/glean/issues/5)。只把源码实际支持的能力列为能力；仓库更新日期是 GitHub `pushed_at`，不能证明数据源仍有效。这里的“可运行”区分本地程序能启动、真实平台接口能返回数据、能持续产出经核验的活动，三者不能互相替代。

## 结论

没有找到一个同时具备**多类奖励活动自动发现、可复核的实时数据、明确许可证、低门槛部署**的成熟现成方案。最接近可复用的部件是 MIT 的 [crypto-alpha-feed](https://github.com/Clawthority/crypto-alpha-feed) 的 RSS 采集/去重，和 MIT 的 [web3-agent-kit](https://github.com/ulsreall/web3-agent-kit) 的跨任务平台发现代码；前者仅给公告线索，后者的目标接口实测受限。覆盖较广的 [web3-airdrop-alpha-agent](https://github.com/monkeydjl/web3-airdrop-alpha-agent) 有实际 collector 代码，但无仓库许可证、默认关闭多个源，部署与密钥成本较高。不能把 README 的“覆盖平台数”视作当前可用活动数。

## 空白与复用边界

1. **活动发现**：RSS/平台 API 可以产出线索，但需要官方活动页、开放时间、名额、费用、可交易性、反钓鱼来源和“已结束”校验；以上仓库均未在本次证明端到端的实时质量。
2. **钱包资格查询**：地址命中历史快照与“现在能领取”不同；claimable 的预计算数据只能证明历史查询模式，不能替代官方 claim 合约/页面核验。
3. **自动执行任务**：`web3-agent-kit` 的执行器与 `RogueAgent` 的模型工作流超出只读发现；不应因仓库宣称支持自动参与，就把它列为无风险活动源。
4. **许可证**：无明确仓库许可证的公开源码不能默认复制或部署。候选中有许可且与目标相关的优先从 `crypto-alpha-feed` 的采集骨架和 `web3-agent-kit` 的数据模型研究，但先以小范围只读验证各源。

核验方式：GitHub Search/Repos API 查询 `pushed_at`、stars、license；浅克隆固定提交，逐项读实际运行路径；仅 Clawthority 做了本地 RSS fixture 端到端验证；其余可运行判断均按上述证据降级，不代表生产可用。
