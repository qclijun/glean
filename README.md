# Glean 拾穗

聚合 Web3 奖励活动，结合预期收益、参与成本、时间投入与风险，提供有依据的参与建议与推荐指数。

Glean 希望帮助用户从分散的公告和社区信息中，找到低门槛、低成本、低耗时、具备变现可能的机会。每个活动都展示参与条件、奖励类型、成本、风险与来源，方便判断是否值得进一步研究。

当前为**人工策展的前端工作台**，内置数据是 **2026-10-26 的研究快照**。活动状态、报价及资格可能变化，参与前应重新核对项目最新规则。

## 当前功能

| 功能 | 说明 |
| --- | --- |
| 活动发现 | 按类别、网络、风险和状态组合筛选，支持关键词搜索 |
| 优先级排序 | 按推荐指数、预计耗时或截止日期排序 |
| 活动研究 | 展示奖励、费用、编辑观察、风险、评分拆解及原始来源 |
| 个人观察清单 | 收藏活动、勾选参与步骤，刷新后保留记录 |
| 收益计算器 | 将获奖概率、Gas、其他费用和时间成本纳入估算 |
| 活动线索草稿 | 在当前浏览器保存待审核线索，尚未发送到服务器 |
| 内部线索收集 | 本地 CLI 从配置的官方 RSS/Atom 订阅源收集待核验条目，重复运行去重 |
| 手机浏览 | 响应式布局及移动端导航 |

网站没有自动采集、实时价格、用户账户后端、合约审计或钱包签名功能。CLI 收集的线索只写入本机文件，不会进入网站。网站中的“提交活动”保存为**本地草稿**；向项目维护者提供线索，请通过 GitHub Issues。

## 快速开始

需要 Node.js **22.18+**（建议 24）、npm 和 Git。当前本地开发无需 API Key 或环境变量。

```bash
git clone https://github.com/qclijun/glean.git
cd glean
npm ci
npm run dev
```

浏览器打开 Vite 输出的地址，默认是 <http://localhost:5173>。开发服务绑定 `0.0.0.0`；端口已被占用时，Vite 可能选择下一个可用端口。

### 常用命令

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动开发服务 |
| `npm run build` | TypeScript 检查并生成 `dist/` |
| `npm run preview` | 本地预览生产构建，默认端口 4173 |
| `npm test` | 运行评分、筛选及收益计算的逻辑测试 |
| `npm run collect:leads` | 抓取配置的 RSS/Atom 订阅源，更新本地待核验队列 |
| `npx playwright test` | 运行浏览器交互测试 |

生产构建与预览：

```bash
npm run build
npm run preview
```

`dist/` 可部署到静态网站托管服务。预览命令用于本地检查构建结果，正式托管需另行配置。

## 信息来源与核验

活动信息按来源类型标记，当前由人工整理：

- **平台官方公告**：例如 Binance Wallet 和 BNB Chain，用于核对活动规则、期限和资格。
- **项目原始页面**：例如活动页、铸造页、白皮书，保留项目自述与安全审计的区别。
- **社区与媒体线索**：例如 X 的公开检索结果、Binance Square、生态目录及媒体报道，用于发现活动和交叉核验。

奖励截图、历史挂牌价格和社区口述利润，不直接作为可实现收益。此次研究中的 X 直读渠道需要登录，未取得受限原帖全文。逐项证据与限制见 [活动核验记录](docs/research.md)。

### 示例：Ptah Relic 与 Proof of Agent

| 项目 | 当前收录方式 | 核心区别 |
| --- | --- | --- |
| Relic Genesis | 首发铸造已结束，作为历史案例归档 | 每 Agent ID 最多 4 枚，可交易；历史价格标注第三方来源 |
| Proof of Agent（POA） | 独立收录的社交奖励活动快照 | 免费铸造但 Gas 另计，卡片不可转让，奖励取决于活动规则与抽选 |

“可出售”不保证存在买盘或足够流动性，“免费铸造”也不等于零总成本。Relic 的历史条件和收益不能直接外推到当前市场。

## 如何判断是否值得参与

### 推荐指数

各维度由编辑给出分数，再按权重加总并四舍五入：

| 维度 | 权重 | 主要考虑 |
| --- | --- | --- |
| 奖励透明度 | 25% | 奖励类型、发放规则和可实现价值是否清楚 |
| 成本友好度 | 25% | 铸造、Gas、手续费用与资金占用 |
| 时间效率 | 20% | 首次操作和持续维护的时间投入 |
| 风险可控度 | 20% | 授权、合约、流动性和资格限制 |
| 证据完整度 | 10% | 原始来源及独立核验的完整程度 |

同时应用以下限制：

- 单人现金收益未知：最高 **69** 分。
- 高风险或尚未开放：最高 **49** 分。
- 已结束：归档，不展示当前推荐分。

多个限制同时满足时采用更低的上限。推荐指数反映研究优先级，不能作为收益率、中奖率或安全认证。规则实现见 [`src/model.ts`](src/model.ts)。

### 预期净收益

```text
预期净收益
= 可变现奖励金额 × 获奖概率（%）÷ 100
  − Gas − 其他直接费用
  − 参与小时数 × 每小时的时间价值
```

计算器以 USD 为金额单位；代币数量需要先换算成可实现的金额。金额、概率和费用均由用户填写，演算示例是假设数字，未接入实时买盘。奖励金额或概率留空时显示 `UNKNOWN`。

结果未量化本金损失、合约风险和价格波动。锁定本金不直接作为费用扣除，但需另外考虑资金占用和可能损失。

## 数据维护与本地存储

活动快照与 `SNAPSHOT` 日期位于 [`src/data.ts`](src/data.ts)，数据类型和评分规则位于 [`src/model.ts`](src/model.ts)。新增或更新活动时：

1. 使用唯一且稳定的 `id`，填写奖励、费用、资格、时间和截止信息。
2. 区分 `active`、`upcoming`、`ended` 状态；未知现金收益设置 `unknownReward`。
3. 按代码中的维度顺序填写 `dimensions`，补充评分依据、风险及参与步骤。
4. 保留原始来源 URL，标记 `official`、`project` 或 `community` 类型。
5. 更新快照日期并重新核对状态；“即将结束”的日期窗口目前也固定在 `src/model.ts`，维护时需一并检查。

收藏、参与步骤和线索草稿保存在当前浏览器的 `localStorage`，没有跨设备同步。清除站点数据或更换浏览器会失去这些记录。草稿只应包含公开活动信息。

### 内部线索队列

运行 `npm run collect:leads` 后，CLI 从 [`config/lead-sources.json`](config/lead-sources.json) 读取官方订阅源，把近 30 天以及未标注发布日期的条目写入被 Git 忽略的 `.glean/leads.json`。首次运行会收集窗口内的历史条目；后续运行按来源 ID 和条目 URL 去重，保留已存线索。也可通过 `npm run collect:leads -- --sources /path/sources.json --output /path/leads.json` 指定配置和输出路径。测试使用本地 RSS/Atom 服务，不依赖外部网站。

所有条目初始状态都是 `unverified`：订阅源文章只是**活动线索**，并不代表已经确认存在奖励活动。人工核实主办方规则、资格、奖励、费用与截止时间后，才应考虑写入 [`src/data.ts`](src/data.ts) 的公开快照。当前仅内置一个已验证可读取的 Ethereum Foundation 官方订阅源；更多来源可在配置中增加。抓取失败时命令退出非零且不改写现有队列。

## 开发与验证

技术栈为 React 19、TypeScript、Vite 和 Lucide；浏览器测试使用 Playwright。依赖版本以 [`package-lock.json`](package-lock.json) 为准。

```bash
npm test
npx playwright install chromium
npx playwright test
```

逻辑测试覆盖评分上限、Relic/POA 区分、组合筛选和成本公式；浏览器测试覆盖详情弹窗、搜索筛选、收藏与清单持久化、计算器、本地草稿及手机导航。

Playwright 会启动或复用 `127.0.0.1:5173` 的服务。运行前确保该端口上的服务属于本项目；测试配置见 [`playwright.config.ts`](playwright.config.ts)。

## 风险说明

本站提供独立研究信息，不构成投资建议或项目背书。参与活动前应自行核对域名、资格、合约权限和钱包中的实际费用；收益未知不代表零风险。
